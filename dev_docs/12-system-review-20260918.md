# Cube / Duel 整体审查（2026-09-18）

## 范围

检查玩家身份与比赛鉴权、选牌/构筑/对阵错误恢复、SSE 连接生命周期、独立 Duel 建房/选卡组/保存/搜索/详情/对局重连，以及 main 与两套 Aly 发布的一致性。结合既有 API、协议和卡片资源测试；本轮未更新卡库或宿主二进制。

## 回归与边界

Windows/Linux API 19 套 212 项、协议 31 项通过；合并后的 Web 31 项通过。两端生产构建通过，Linux 分别构建 Cube 与带 /duel-api、/duel-assets 的 Duel standalone，包含 static/public。

Windows/Linux 隔离真实宿主 BO3、重连与录像帧检查通过。浏览器检查桌面/手机布局、卡片完整描述和同名、禁限表切换、持久保存及反馈恢复。发布后补验公网 HTTPS/WSS 对局与页面静态资源，具体提交、build ID、备份和结果写入发布审计。

仍保留既有产品约束：卡组保存在当前浏览器，最多 8 副，建议导出 YDK；未扩展为账号云同步。房间链接与密码等价。审查与样例回归不能证明所有卡片效果或所有网络时序均无缺陷。

## 分支与发布

用户已明确授权推送 fc-jian/ygocube 与 fc-jian/srvpro。先推 srvpro/cube，再推根仓库 main、codex/cube、codex/duel 和已建 archive 标签；确认归档存在且旧分支无独有提交后删除两条旧远端分支。不强推，不改 upstream。

main 是两套应用共同生产分支；开发分支通过普通 merge 进入 main，之后快进到生产基线，仅保留两个开发分支。Aly 采用 main 源码的 Linux 产物，激活前确认没有活动宿主，备份数据库与配置，原子切换两套 current。保留旧 release 与备份，服务或静态资源验收失败则回滚。
