# 06 - cube 前端当前交互设计（Next.js）

> 实现目录：`cube/apps/web`。页面是服务器状态的投影；SSE 只作为刷新提示，
> 浏览器断线后会重新请求完整的玩家状态。

## 1. 路由与身份

| 路由 | 用途 |
| --- | --- |
| `/` | 首页与创建比赛入口 |
| `/create-tournament` | 创建比赛，选择卡池和明确赛制 |
| `/t/:tid` | 报名页 |
| `/t/:tid/draft/:pid` | 选牌页 |
| `/t/:tid/deck/:pid` | 构筑页 |
| `/t/:tid/matches/:pid` | 对局房间与结果 |
| `/t/:tid/ranking/:pid` | 排名 |
| `/pool/:name` | 公开只读卡池浏览（合法 URL 名称） |
| `/admin` | 管理比赛、参数、卡池和回溯 |
| `/admin/pool/:id` | 卡池编辑页（`new` 可建立新池） |

玩家 token 存在 `localStorage` 的 `yc_token_<tid>_<pid>`，缺失时显示输入框；
关闭该比赛 token 鉴权后只需 tid+pid。super token 可以作为调试用万能玩家 token。
顶栏还提供退出登录、本地卡图目录授权和字体大小设置。
报名阶段右上角的身份区域允许玩家修改自己的显示名称；修改需要玩家 token，
写入 `player_rename` 事件，进入选牌后按钮隐藏。卡池预览期间顶栏提供“准备”按钮，
并可展开查看全部报名玩家及准备状态；状态写入 `player_ready` 事件。令牌按钮首次
点击显示令牌，再次点击复制到剪贴板。报名页输入已存在的 player ID
时不再重复调用 join，而是直接跳转到该玩家页面，由页面提示输入原 token。

报名卡池预览提供“默认/抓位（早→晚）”排序；抓位排序按当前卡池统计的平均抓位百分比
升序排列，无统计卡置后并保持原顺序。

## 2. 选牌页

### 2.1 顶部状态

`TopBar` 显示比赛名/阶段/冻结状态、人数、赛制、模式、卡池、deck limits 和
每堆大小。passing 模式从左到右按服务器当前 `seat` 展示所有玩家队列长度，
每轮换位后随状态刷新；同时显示“还可获得”的精确数量（完整公平轮）或预计
数量（非整轮）。

选牌倒计时使用服务器绝对 `deadlineAt`，前端每秒 tick。passing 中即使当前
没有队首牌堆，顶栏仍显示自己的 reserve 余额；基础 40 秒耗尽后明确标红
“保留时间”。暂停/冻结时显示服务器保存的剩余毫秒，而不是重新计时。

创建比赛和报名阶段管理员编辑使用同一组牌堆参数。默认不勾选“按比例配置额外卡”；
勾选后百分比输入默认 `25`，范围为 `0--100` 的整数，并显示完整牌堆的主卡/额外卡
数量。启用比例时旧的 `packStrategy` 下拉框禁用并提示比例优先；取消勾选后恢复
旧策略。比例资源不足时管理员开始选牌会看到主卡/额外卡需求与可用数量的错误报告。

### 2.2 右侧牌堆

- 自己可选的队首牌堆显示正面卡图；其他玩家只能看到数量和卡背。
- 桌面端一行 **6 张**，小屏自动降为 3 张；区域 `overflow-y-auto`，超出屏幕
  可滚动，不裁切牌堆。
- 点击或拖动卡牌都先弹确认；点击牌打开详情的同时将其记为本人当前堆的候选牌，
  候选牌名称显示在顶部状态栏，超时自动选择优先使用最后点击且仍在堆中的牌；
  选牌后可指定 main/extra/side 目标区，类型不符时前端和后端都会拒绝。
- 当前可见牌堆默认按 YGOPro `deck_sort_lv` 整理显示；标题提供“默认/抓位（早→晚）”
  选择。两种模式都只改变当前玩家看到的排列，不改变服务器牌堆/选牌顺序，也不提供
  会误导用户的手动持久化排序按钮。
- 悬停详情按视口宽高动态调整尺寸和左右/上下位置；触摸设备不显示跟手浮窗，
  点击改为屏幕内可滚动的固定详情。
- 初始弃置列表只有在 `dropPublic=true` 时显示；可搜索卡名/编号。

### 2.3 左侧已选/已构筑区域

三个区域按 cards.cdb 类型限制：main 不收额外卡，extra 只收额外卡，side 可
收两类。卡片支持区内插入、跨区拖动和搜索过滤；服务器数组顺序是唯一事实源，
因此新加入的卡永远追加到末尾，手动拖动不会被下一次刷新覆盖。

## 3. 构筑页

构筑页复用相同的三个 `DeckZone`，右侧显示未使用区/搜索结果。提供：

- “整理卡组”：一次按 YGOPro `deck_sort_lv` 逻辑整理 main、extra、side；
- “随机排序”：只随机 main，用于模拟洗牌和抽卡；
- 手动拖动仍可改变顺序，整理不会自动执行；
- 逐条显示主/额外/副上限、已选许可和不合规错误；
- 下载命名为 `cube-deck-<tid>-<pid>-<timestamp>.ydk`；锁定后可在时限内解锁。

构筑阶段若管理员手动确认进入对战，页面通过 SSE/短轮询自动刷新；右上角显示
醒目的“立即前往对战”提示。未合规玩家会先显示警告，确认后服务器随机修复，
main 不足下限则标为 DSQ。

## 4. 对局与排名页

对局页只显示当前玩家相关桌号、对手、房间名、连接状态和比分，并提供下载当前锁定
`ydk` 与返回构筑页按钮。房间名使用 `CUBE-` 加稳定短摘要，玩家从 `/meta` 取得
srvpro 公网 host/game port，复制房间名后用 YGOPro 客户端加入；不向玩家广播其他桌的
房间名或 deck。

排名页显示胜 3、平 1、负 0、净胜局和 OMW 等公开排名字段。SSE 收到对局事件后
刷新本人的对局列表；管理员手动录入/推进后玩家端也会自动回到对应页面。

## 5. 卡图、卡名和搜索

`CardImage` 的加载顺序：

1. 玩家授权的本地 YGOPro 根目录 `pics/` 或 `expansions/*/pics/`；
2. 服务端 `GET /pics/:code.avif` 低清缩略图；
3. 可选的服务端 `GET /pics/:code` 原图只读代理；
4. 带卡名的空白占位卡。

原始 pics 永不写入 cube 数据库。所有卡牌 hover 都显示放大图、字面原名、编号
和 `desc` 效果文本；点击固定详情还显示类型、种族、属性、等级/RANK/LINK、攻守、
Link 标记、字段名称以及 alias 规则关系。字段 code 仍保留在元数据和搜索索引中，但不在
玩家卡片详情中显示。种族/属性按位掩码展示。
带卡池上下文的卡牌详情还显示 `平均抓位：X.XX（X.XX%）` 以及参与统计的牌包数和
比赛数；统计只来自完整抽取、非 `test*` 比赛，按 exact code 和卡池 ID 分开累计。
公开 `/pool/:name` 页面与报名预览保持相同的主卡/额外卡布局，并实时轮询统计更新；
页面顶部提供浏览器级本地 YGOPro 卡图目录绑定/解绑，复用报名页的目录授权设置；
默认维持卡池原顺序，同时可按平均抓位百分比正序或逆序排列，未参与统计的卡放在有
统计卡之后且保持原顺序。管理卡池列表提供公开链接。
搜索覆盖名称、编号、效果、类型/种族/属性/等级/攻守/字段名称和字段 code；name/code
始终是 exact card row，不因 alias 改写。搜索输入按空白拆分为多个关键字，所有关键字都必须
在索引字段中命中（AND）；不设隐含的 30/50 条上限，结果区域自行滚动。排序先按卡名命中的
关键字数量降序，再按靠前关键字是否命中卡名逐项优先，最后才显示仅命中非卡名字段的结果。

选牌搜索状态按当前玩家视角返回 `not_in_pool/dropped/picked/seen/unknown`：只有
玩家选牌前实际仍在牌堆中的卡标为 `seen`，已被别人先选走的卡保持 `unknown`。
构筑阶段搜索改用全局真实状态，显示四类 `不在卡池/初始排除/已选/其他玩家已选`，
不受当前玩家是否曾经看到该牌影响；初始排除也不因隐私配置而误显示为未知。

卡池编辑页按同一 `sortCardCodes(..., 'lv')` 逻辑整理主卡与额外卡，不能出现
前端排序与 YGOPro 卡组编辑器不一致的情况。导入 `code<TAB>name` 时，页面必须
展示后端返回的所有 missing/name mismatch/invalid 警告，不可静默丢行。

## 6. 管理页

管理页提供：

- 建立/编辑比赛参数（与创建页相同字段，构筑时间空值表示无限）；
- 选择卡池；比赛专有管理 token 通过 scoped 只读接口查看全部卡池，只有 super admin
  可以设置默认卡池、导入、编辑或删除；
- 设置明确赛制、瑞士轮数和淘汰人数；
- 开始选牌、冻结/解冻、暂停/恢复、手动结束构筑；
- 手动重设比赛 admin token、玩家 token、关闭 token 鉴权；
- 查看不合规卡组报告，确认随机修复后进入对战；
- 给指定玩家增加 reserve 保留时间；
- 事件时间线、回溯预览和冻结状态下的硬回溯。事件 hover 显示选牌卡号、玩家、
  牌堆和 reserve 调整等具体细节，回溯恢复候选牌与 reserve 余额。
- super admin 专属“比赛创建权限用户”面板：创建用户名并一次性显示/复制随机 token，
  删除后立即失效。创建比赛页填写用户名 + token（super token 可留用户名为空），
  不再提示配置文件 create token；比赛列表与状态显示创建者。

卡池页面的排序按钮是显式操作，不会因为搜索、加入或删除卡片自动重排。

## 7. 实时性与脱敏

`useTournamentStream()` 监听 `phase`、`pack`、`pick`、`pause`、`deck`、`match`、
`notice`，断线指数退避重连且卸载时取消待执行重试。SSE 使用
`yc_pid_<tid>/yc_token_<tid>` cookie，不把 token 拼入 URL；回调放在 ref 中，页面
render 不会反复重建连接。事件只包含状态摘要：

- `pick` 不含 card code；
- `deck` 不含卡组内容；
- `match` 不含其他桌 room name；
- 他人队列只含数量，不含牌面。

收到事件后页面调用 `/t/:tid/state` 获取本人视角状态；服务器绝对截止时间避免
SSE 延迟造成倒计时漂移。

## 8. 验收清单

1. 选牌时他人牌面不会通过 DOM、SSE 或 API 泄露；passing 座位顺序实时变化。
2. 右侧牌堆桌面端六列、超屏可滚动；点击/拖动均有确认和类型校验。
3. 构筑“整理”和“随机排序”都是独立按钮；手动顺序可持久化，卡池编辑页
   使用相同整理逻辑。
4. 管理员进入对战后，玩家页面自动刷新并显示明显的对战入口；暂停前后倒计时
   保持相同剩余值。
5. 本地缺少卡图时逐级 fallback 到 AVIF/代理/占位，不阻塞构筑。
